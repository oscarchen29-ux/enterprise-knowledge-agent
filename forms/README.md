# forms/ — 行政程序的標註標準答案

這個資料夾放的是**人工標註的標準答案**,用來評測 Agent 能不能從法規文件推導出
「使用者要完成一項程序,必須滿足或提供哪些東西」。

`docs/` 是知識庫(Agent 讀得到),`forms/` 是標準答案(Agent **讀不到**,只有評分程式讀)。
兩者絕對不能混,否則就是把答案直接餵給受測者。

## 目前有兩張表單,而且結構刻意相反

| | 英語檢測獎勵 | 宿舍床位申請 |
|---|---|---|
| 核心條件 | 數字門檻(多益 860、雅思 6.5、寫作 150…) | **完全沒有數字門檻** |
| 資格結構 | 四種互相獨立的給付 | 十款身分資格,**符合任一即可**(選言) |
| 來源文件 | 兩份(校級要點 + 資工系申請表),**互相矛盾 6 處** | 一份(線上申請,無紙本表) |
| 特殊結構 | 跨條文推理:成績不符但低收入戶另有補助 | 兩階段(抽籤 -> 線上確認)、狀態降級 |
| 主要幻覺考點 | 申請表有 FLPT 但法規查無標準 | 全文無任何具體日期,問截止日會不會編 |
| 測試案例 | 20 題 | 19 題 |

**為什麼要兩張**:只做一張,無法回答「你是不是挑了一個好做的例子」。
兩張的條件結構相反,方法若在兩張上都成立,才有一般性可言。

## 標註怎麼產生的

1. Claude 先自己讀原始法規,寫出初稿。
2. 另外派**三個獨立 agent 盲讀**同樣的文件(不同角度),再加一個完整性稽核 agent。
3. 比對四份獨立結果與初稿,合併差異。

**這一步抓到真正的錯誤,不是形式而已**:

- 英語檢測獎勵:初稿漏掉 5 項前置條件,並且**標錯 1 項** —— 初稿斷言「受理單位是
  語文教學中心,非系辦」,但申請表上有「學系初審」與「系主任審核」兩級核章,
  兩者關係文件沒寫清楚。已改為 X5。
- 宿舍床位申請:初稿漏掉第二點(二)括號內的「在職專班生除外」、第二點(一)明文
  「含休學、延畢生」(休學不得作為擋件理由)、以及第六點(二)違規點數達 10 點是
  「**取消保障、同一般生抽籤**」而非不予申請 —— 與勒令退宿的「不予申請」後果不同。

標註標錯的話,後續所有量測都是錯的。所以這一步不能只靠一個人讀一遍。

## 關鍵概念

**前置條件(preconditions)**:完成這項程序必須滿足的東西。分兩種 ——
- `需向學生詢問: true` -> Agent 必須主動問,沒問就算**漏問**
- `需向學生詢問: false` -> Agent 必須主動告知,學生不會自己問

**文件不一致 / 原文歧義**:這**不是標註錯誤**,是原始文件本來就矛盾或留白
(英語獎勵的申請表是 2019 年版、要點是 2026 年 1 月修正;宿舍要點對學期中途申請
刻意不規定)。正確行為是**指出落差並建議洽詢**,不是自己補一個答案。
這些是最好的幻覺考題。

**隱藏檔案(profile)**:模擬學生只有在 Agent 問到某個 key 時才透露該值,沒問就不講,
問到不存在的 key 回「我不知道」。這樣才能量出 Agent 自己判斷缺什麼的能力。
模擬學生**用查表實作,不要用 LLM 生成** —— 用 LLM 會引入第二層不確定性,
理由同 `benchmark/inclusion_accuracy.py` 不採用 LLM 當裁判。

## 評測指標

| 指標 | 怎麼算 |
|---|---|
| 漏問率 | `must_ask` 裡沒被問到的比率。**規則寫寬,所以是下界** |
| 冗餘提問率 | 問了 `must_not_ask` 裡項目的比率 |
| 資格判定正確率 | 最終判定是否等於 `verdict` |
| 告知完整率 | `must_tell` 裡有多少被主動講出來 |

比對規則在 `benchmark/forms_config.py`,是關鍵字正規表示式,不是用 LLM 判讀。

## 怎麼跑

```bash
python benchmark/precondition_probe.py --form 英語檢測獎勵 --models qwen2.5:14b qwen2.5:7b --repeats 3
python benchmark/precondition_probe.py --form 宿舍床位申請 --models qwen2.5:14b --cases S02 S08 S14
```

預設會**續跑**(跳過 out 檔裡已完成的),所以斷線最多損失正在跑的那一題。
