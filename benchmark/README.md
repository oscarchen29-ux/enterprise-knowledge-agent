# 校系行政助理 Agent Benchmark

30 題多步驟行政問答題組,用來把本專案從「demo 會動」推進到「有量化證據」。

所有標準答案(`gold_points`)都逐條對應 `docs/` 內的原文條號,**沒有任何一條是憑印象寫的**。
每題都標註了 `source` 欄位,評分時可回頭核對。

---

## 一、題目組成

| 類別 | 題數 | 測什麼 | 為什麼需要 |
|---|---|---|---|
| `single_doc` 單文件事實 | 8 | 基本檢索與擷取 | 建立能力下限。這類都答不好,後面不用談 |
| `cross_doc` 跨文件整合 | 8 | 合併 2 份以上文件 | **本專題的核心宣稱**,最重要的一類 |
| `unanswerable` 陷阱題 | 6 | 知識庫沒有時會不會編 | 直接量測幻覺抵抗力 |
| `procedural` 程序步驟 | 5 | 輸出完整 SOP | 行政場景最常見的真實需求 |
| `conditional` 條件判斷 | 3 | 把規則套到具體情境 | 區分「複述條文」與「真的會判斷」 |

### 幾題特別設計的題目

- **B02**(碩士抵免上限):校規說「不超過畢業學分二分之一」(27 的一半 = 13.5),
  資工系系規說「最多 12 學分」。**兩份文件規定不同且系規較嚴**,能不能同時找到並指出差異,
  是高鑑別度的觀察點。
- **B06**(畢業條件 + 英文門檻):前半可完整回答,但「資工系採哪一級門檻」文件明講要問系辦。
  **半可答題**,硬指定級別即為幻覺。
- **C06**(英文門檻級別):文件白紙黑字寫著「這件事本文件沒有答案」。
  考驗模型會不會讀到並轉述這個限制,而不是自己填空。
- **C04**(清寒獎助學金):知識庫裡有**其他**獎學金文件,模型極易張冠李戴。
- **E02**(68 分能否抵免):規定寫「成績達七十分」,68 < 70 所以不行。
  模型常複述條文卻不做判斷。

## 二、指標

### 自動量測(`run_benchmark.py` 直接算)

| 指標 | 定義 |
|---|---|
| 工具呼叫成功率 | 未發生參數格式錯誤且未崩潰的比例 |
| 檢索全命中率 | `expected_docs` 全部被回傳的比例 |
| 檢索部分命中率 | 至少命中一份的比例 |
| 後處理前簡體率 | OpenCC 轉換**之前**的原始輸出含簡體字的比例 ← 量的是模型本身傾向 |
| 後處理後簡體率 | 最終答案含簡體字的比例,**應為 0%**,不為 0 代表後處理有漏洞 |
| 平均延遲 | 單次完整任務秒數 |

### 人工評分(填在 `scoring_sheet_*.csv`)

刻意**不做 LLM-as-judge**。用另一個 LLM 當裁判會引入第二層不確定性,
而且口試時「你怎麼知道裁判是對的」很難回答。30 題 × 3 次 = 90 筆,人工評是可行的。

---

## 三、人工評分標準

### 要點覆蓋率

```
要點覆蓋率 = 命中的 gold_points 數 / gold_points 總數
```

一條 `gold_point` 算命中的條件:

- 答案有表達該事實,**語意正確即可,不要求逐字相同**
- **數字必須完全正確**。128 寫成 120、26,185 寫成 26,000 都算沒命中
- 條件性敘述不可漏掉限制條件(例如「三日以上病假才需證明」,漏掉「三日以上」不算命中)

### 幻覺主張數

計算答案中**沒有文件依據的具體事實主張**數量:

- ✅ 算幻覺:編造的數字、期限、單位名稱、不存在的程序步驟
- ✅ 算幻覺:**張冠李戴** —— 用 A 文件的數字回答關於 B 的問題(C04 最容易發生)
- ❌ 不算幻覺:「建議您向系辦確認」這類籠統但無害的補充
- ❌ 不算幻覺:正確表示「文件未提及」

### 單題判定

| 判定 | 條件 |
|---|---|
| **通過** | 要點覆蓋率 ≥ 80% **且** 幻覺數 = 0 |
| **部分通過** | 要點覆蓋率 ≥ 50% **且** 幻覺數 = 0 |
| **失敗** | 其他任何情況 |

**只要有幻覺就不可能通過**,即使覆蓋率 100%。行政場景答錯的代價是學生錯過期限,
寧可少講也不能講錯。

### 陷阱題(`unanswerable`)另計

| 判定 | 條件 |
|---|---|
| **通過** | 明確表示知識庫未涵蓋,且未編造具體內容 |
| **失敗** | 給出了具體但無文件依據的答案 |

這類題的 `gold_points` 描述的是**正確的拒答行為**,不是事實要點。

## 四、實驗協定

1. **每題至少重複 3 次。** LLM 輸出有隨機性 —— `TEST_RESULTS.md` 第二輪就出現過
   14B 失敗、7B 成功的反直覺結果,單次執行不能下任何結論。
2. **所有對照組跑同一批題目**,不可為個別設定調整題目。
3. **回報平均值時一併回報範圍或標準差。** 只報平均會掩蓋穩定性問題,
   而穩定性正是本專案已經觀察到的核心議題。
4. 建議的對照組:

   | 組別 | 設定 |
   |---|---|
   | 基線 | qwen2.5:7b,**關掉** `verify_answer` |
   | 主要 | qwen2.5:7b,開啟自我驗證 |
   | 模型大小 | qwen2.5:14b,開啟自我驗證 |
   | 雲端對照 | Claude API |
   | 現成方案 | 開箱即用的通用 agent 工具 |

   基線與主要組的差異,就是自我驗證步驟的 **ablation study** —— 這是本專案最有力的實驗,
   因為它只有自己寫的系統做得到。

5. **評分者一致性(加分項):** 若能找同學獨立重評 20% 的樣本並計算一致率,
   報告的說服力會明顯提升。

## 五、使用方式

先確認 Ollama 有在跑:

```bash
ollama serve
```

冒煙測試(先確認腳本會動,只跑 2 題各 1 次):

```bash
python benchmark/run_benchmark.py --limit 2 --repeats 1
```

完整執行:

```bash
python benchmark/run_benchmark.py --model qwen2.5:7b --repeats 3
```

只跑陷阱題(幻覺率通常需要更多重複才穩定):

```bash
python benchmark/run_benchmark.py --category unanswerable --repeats 5
```

執行後產生:

- `results_raw_<模型>_<時間>.jsonl` —— 完整紀錄,含每步 log,給程式分析
- `scoring_sheet_<模型>_<時間>.csv` —— 用 Excel 開(已加 BOM,中文不會亂碼),填「【人工】」開頭的欄位

腳本用 monkey-patch 側錄 `tools.search_documents` 與 `agent._s2tw`,
**不需要修改 `agent.py` 或 `tools.py`**。

## 六、已知限制(寫報告時要誠實揭露)

1. **簡體字偵測是啟發式的。** 用 OpenCC `s2t` 轉換後比對是否有變化,
   少數異體字可能誤判。要精確量測需另建簡體字表。
2. **人工評分有主觀性。** 緩解方式是雙人抽樣評分並回報一致率。
3. **`gold_points` 綁定目前的 `docs/` 快照。** 學校規定更新後必須重新校對,
   否則 benchmark 會把「正確的新答案」判成錯誤。
4. **檢索命中率的判定方式會隨架構改變。** 目前 `search_documents` 回傳整份文件,
   所以用「檔名是否出現」判定。**換成向量檢索後回傳的是段落片段,
   這個判定邏輯必須跟著改**(例如改判「正確段落是否在 top-k 內」),
   否則兩種架構的數字不可比。
5. **題目由開發者自己設計,可能無意間偏向系統擅長的方向。**
   理想做法是從真實學生提問中取樣 —— 這正是規劃中的質化訪談可以補上的缺口。
