系辦助理 Agent:本地端受管制領域問答的可行性評估

以校系行政作為第一個驗證場域,目標是建立一套可遷移到其他文件密集領域的評估方法。原型已可運作,想在投入正式評估前,先與老師確認研究定位、對照組設計與訪談可行性。

01目前進度

暑假期間已完成一個可實際運作的本地端原型,能處理需要跨多份文件才能回答的行政問題。

  • 執行環境:Ollama 搭配 qwen2.5(7B / 14B),全程本地推論,文件不外流。
  • 系統結構:planner-executor 迴圈 + 文件檢索工具 + 自我驗證步驟,並以 provider 抽象層封裝模型後端,之後可直接替換為雲端 API 或系上 GPU 推論服務。
  • 知識庫:17 份暨大公開行政文件,涵蓋學則、資工系必選修科目表、學位論文格式、獎學金與外語畢業門檻等。
  • 已驗證能力:可回答需同時查閱兩份文件的問題,例如「轉系生轉入三年級的抵免上限」與「畢業應修總學分」。

這部分是目前最具研究價值的材料 —— 每一項都是先出現失敗案例,才回頭找到原因並修正。

03研究問題

  • RQ1　本地開源小模型在中文校務文件的多步驟問答上,答案正確率與工具呼叫成功率為何?
  • RQ2　自我驗證步驟能否有效降低幻覺率?降幅多少?
  • RQ3　相較於通用 agent 框架直接套用,領域化設計帶來多少實質改善?
  • RQ4　系辦人員與學生實際試用後,認為可用或不可用的原因為何?(質化)

04長期延伸方向

校系行政之所以適合作為第一個場域,是因為它同時具備三個特徵:文件密集、規則明確、答錯有實際代價,但取得資料與受訪者的門檻低。這三個特徵在其他領域同樣成立,因此本專題真正想產出的是一套可換場域的評估方法,而非單一工具。

延伸場域可行性評估
中小企業內部規章、家庭文書 近期最可行。文件性質與校系行政接近,風險等級相當,可直接沿用同一套 benchmark 題型結構
法律文件檢索 中期。技術可遷移,但須明確區隔「條文檢索」與「法律意見」,後者涉及律師法規範
醫療 長期,且須額外條件。病歷屬特種個資,錯誤答案有實質傷害風險,需先取得倫理審查與領域專家共同設計評估標準,不在本專題範圍內

為支撐遷移性,系統設計上會將領域描述與知識庫抽離為設定,更換場域不需修改 agent 邏輯;benchmark 也會以題型結構(單文件查詢、跨文件整合、文件未涵蓋的陷阱題)為骨架,僅替換題目內容。

05想向老師確認的三件事

一、研究貢獻的定位

同樣的功能,用現成開源 agent 框架(例如 OpenClaw)也能組出來。因此我認為本專題的貢獻應該落在「量化評估與失效模式分析」,以及第 04 節所述的方法可遷移性,而非主張系統本身的新穎性。想確認老師是否同意這個定位,若不同意,希望往哪個方向調整。

二、對照組設計是否足夠

目前規劃三組對照:(A) 通用框架開箱即用、(B) 本專題的領域化版本、(C) 雲端 API 作為正確率上限參考。若 B 明顯優於 A,即可用數據支持「通用 agent 直接套用於垂直領域並不足夠」這項論點。想請教這樣的設計是否站得住腳。

三、訪談的可行性與倫理程序

質化評估需要系辦人員與學生受訪者。想請教是否適合由老師代為引介,以及此類使用者研究是否需要送校內 IRB 審查、程序大約需要多久。這會直接影響下學期的時程安排。
